# Issue #24 — явная пагинация серверов и доменов

## Цель

Предоставить постраничное получение серверов и доменов через MCP с сохранением `meta.total`. Один вызов получает одну страницу и сообщает количество полученных записей, общее количество и следующее смещение.

Выбрана явная пагинация вместо автоматического обхода: ограничены число HTTP-запросов и размер ответа; ошибка следующей страницы не маскируется частичным успешным результатом.

## Tasks

- [x] 1. **Закрепить контракт параметров и страницы.** Определить `PageParams = { limit?: number; offset?: number }` и результат `Page<T> = { items: T[]; total: number; limit: number; offset: number; nextOffset: number | null }`. Defaults применять только при `undefined`: `limit = 100`, `offset = 0`. Принимать безопасные целые числа: `1 <= limit <= 100`, `offset >= 0`; сумма `offset + limit` также должна быть безопасным целым. Граница 100 — локальная политика нового постраничного интерфейса, а не документированный максимум Timeweb. Явный `null`, неправильные типы, дроби, бесконечности и небезопасные числа отклонять без HTTP. Объект параметров не мутировать. Вызов без параметров и `{}` допустимы.

- [x] 2. **Реализовать методы страницы без изменения старого контракта.** Добавить `ServersApiClient.listServersPage(params?, options?)` и `DomainsApiClient.listDomainsPage(params?, options?)`. Использовать существующий `RequestOptions`, передавая его в GET без изменения общего транспорта. После нормализации параметров отправлять ровно один запрос с явными `limit` и `offset`. Проверять envelope полученного ответа: он является объектом, поле коллекции — массив, `meta` — объект, `meta.total` — неотрицательное безопасное целое. Если записей больше запрошенного `limit`, отклонять ответ вместо неограниченного вывода. Неверный envelope возвращать как безопасный `ServerException`: `kind=invalid_response`, `outcome=unknown`, `semantics=read`; не сохранять сырое тело или причину. Не проводить полную валидацию DTO каждой записи. Старые `listServers()`/`listDomains()` оставить с прежним массивным результатом и одним GET; новым методам не делегировать их, чтобы не потерять metadata.

- [x] 3. **Определить завершение страницы.** Для непустой страницы вычислять `endOffset = offset + items.length`. `nextOffset = endOffset` только при безопасном продвижении и `endOffset < total`, иначе `null`. Не перескакивать на `offset + limit` при коротком ответе. Для пустого массива всегда возвращать `nextOffset: null`. Не подменять `total` длиной массива и не исправлять данные провайдера самостоятельно. Несогласованность количества записей и `total` не использовать как доказательство полного списка или стабильного снимка.

- [x] 4. **Подключить новые actions и тестируемые handlers.** В существующих action-модулях добавить `listServersPageAction` и `listDomainsPageAction`, сохранив старые массивные exports. Новые actions передают параметры и результат страницы без потерь; разрешают инъекцию только необходимых публичных методов клиента. Добавить handler factories по принятому в проекте образцу и сохранить зарегистрированные production handlers. Нормализация параметров должна защищать прямые вызовы и инъецируемые handlers, а не только MCP-вызов. Для неверных параметров выдавать контролируемое сообщение о `limit/offset` и `isError: true` без исходных значений. Ошибки API отображать через существующий безопасный formatter.

## Критерии готовности

- Оба MCP-инструмента поддерживают явную пагинацию, сохраняя `total`.
- Вызов без параметров получает первую страницу с `limit=100`, `offset=0`.
- Валидный вызов выполняет один GET; неверные параметры — ноль запросов.
- Следующее смещение не пропускает записи из-за короткой страницы и не переполняется; пустая страница не запускает продолжение.
- Пустой аккаунт отличается от пустой страницы; противоречивые данные не выдаются за полный список.
- Некорректный envelope не превращается в успешный ответ с выдуманным `total`.
- Старые массивные API-методы и actions сохраняют форму результата.
- Имена инструментов, аннотации чтения, безопасные ошибки и отмена сохранены.
- Соседние проблемы документированы, их реализация не затронута.
- Все обязательные локальные проверки проходят; ограничения перечислены отдельно.
