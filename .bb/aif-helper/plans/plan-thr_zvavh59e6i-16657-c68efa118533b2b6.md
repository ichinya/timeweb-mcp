# Issue #31 — диагностировать нестабильный timeout smoke-start на Windows

## Цель

Сделать результаты smoke-start измеримыми и однозначными, сохранив обнаружение зависаний и проверку чистоты stdout. Выяснить, воспроизводится ли превышение пятисекундного порога, и документировать пределы исследования без предположений о дефекте production-сервера.

Исследование: шесть локальных запусков заняли 1,405–3,252 секунды; два smoke-start и один MCP smoke прошли. Полностью холодный кеш не контролировался. В двух последних проверенных CI runs шаг Verify package был пропущен.

## Ограничения

- Перечитать AGENTS.md, проверить HEAD, git status и diff.
- Сохранить незакоммиченные изменения #28 и #30, включая scripts, README, workflow, LICENSE, метаданные и планы.
- Scope: scripts/smoke-start.mjs, отдельный модуль его логики при необходимости, сценарные тесты, их подключение в package.json и краткая документация исследования.
- Не менять runtime-сервер, MCP SDK, зависимости, lockfile, версию пакета и workflows.
- Сохранить production-порог 5000 мс. Не увеличивать его и не вводить пользовательскую настройку без новых измерений, обосновывающих изменение.
- Не устанавливать инструменты, не запускать авторизованные облачные операции и не читать production .env.
- Не создавать коммит, не выполнять push, публикацию, запуск CI или закрытие issue.
- Измерения после простоя не называть полностью холодным запуском без контроля кеша.
- Исходную причину исторического сбоя считать UNKNOWN, пока она не подтверждена.
