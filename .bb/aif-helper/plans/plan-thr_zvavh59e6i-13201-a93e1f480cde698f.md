# Issue #27 — обновить OpenAPI и проверить совместимость существующих вызовов

## Цель

Обновить локальный OpenAPI из официального источника, перейти на документированный API host и проверить существующие HTTP-вызовы и MCP-инструменты.

Явно классифицировать десять недокументированных вызовов. Исправить подтверждённую ошибку обработки 2FA при удалении кластера БД. Сохранить результаты #24–26 и публичное поведение остальных инструментов.

## Ограничения

- Перед изменениями перечитать применимые AGENTS.md, проверить HEAD, git status и diff. Сохранить несвязанные изменения.
- Scope: локальная спецификация и сведения о её источнике, штатные scripts нормализации/проверки, `src/api/client.ts` в части host, совместимость удаления кластера БД, связанные DTO/actions, тесты, fixtures, README и документация совместимости.
- Не обновлять зависимости, конфигурацию CI, версию пакета и инструменты разработки.
- Не заменять версии API массово. Совпадение назначения endpoints не доказывает совместимость ID, параметров и моделей.
- Не добавлять новые MCP-tools и реализации новых сервисов.
- Не удалять и не перенаправлять недокументированные операции без доказанного основания. Отсутствие маршрута в OpenAPI не считать подтверждённым HTTP 404.
- Не добавлять автоматический fallback между host/endpoints, retries или повторные мутации.
- Не отменять совместимость форматов SSH и баз знаний, JSON-контракт ресурсов и пагинацию #24.
- Проверять offline с fake adapter и сетевым запретом. Не читать production `.env`, не использовать реальные токены, не выполнять облачные операции.
- Не выполнять коммит, push, публикацию, создание новых GitHub issues или закрытие существующих.
- Авторизованные live-проверки и подтверждение production-совместимости остаются отдельным этапом.

## Проверки

- `node --version` — записать совместимый с README runtime.
- `npm run normalize:openapi` — нормализация проходит; повторный запуск не меняет SHA-256 `specs/openapi.json`.
- `npm run validate:openapi` — нет коллизий, повторных operationId и неразрешённых внутренних ссылок; сообщить фактические счётчики.
- Новая проверка маршрутов — все извлекаемые вызовы сопоставлены с OpenAPI либо имеют точное обоснованное исключение; неоднозначные случаи не скрыты.
- `npm run test:transport` — типы тестов, новые fixtures и offline API/MCP-сценарии проходят без внешней сети.
- `npm run verify` — OpenAPI, release-тесты, TypeScript, transport-набор, сборка и оба smoke-теста проходят. Команда включает `test:transport`; отдельный повтор после полного успешного прогона не требуется.
- `git -c safe.directory=D:/Projects/timeweb-mcp diff --check` — нет whitespace-ошибок; новые untracked-файлы дополнительно просмотрены.
- `git -c safe.directory=D:/Projects/timeweb-mcp diff --name-only` и `git -c safe.directory=D:/Projects/timeweb-mcp status --short` — scope соблюдён, несвязанные файлы сохранены, staging отсутствует.

Отдельной команды lint нет; инструменты ради неё не устанавливать. Повторять полный успешный verify только после новых изменений или обнаруженной проблемы.
