# Issue #31 — настраиваемый timeout startup smoke

## Цель

Позволить явно увеличить срок ожидания готовности в медленном окружении, сохранив 5000 мс по умолчанию, обнаружение зависаний, проверку stdout и безопасную диагностику.

Основание: неизменённый сервер на Windows однажды достиг готовности за 7627 мс; последующие запуски были быстрее. Профилирование быстрых запусков не установило причину медленного. Настройка timeout не должна выдаваться за устранение первопричины.

## Ограничения

- Перечитать применимые AGENTS.md, проверить HEAD, git status и diff; сохранить несвязанные файлы и планы.
- Scope: smoke-скрипты, общий разбор настройки, сценарные/CLI-тесты, README и docs/smoke-startup.md.
- Не менять runtime-сервер, зависимости, lockfile, версию пакета, MCP-контракты и workflows.
- Использовать одну переменную: `TIMEWEB_SMOKE_START_TIMEOUT_MS`.
- По умолчанию сохранить 5000 мс. В CI не задавать увеличенный timeout автоматически.
- Настройка управляет только ожиданием готовности startup smoke и startup-series. Она не меняет API timeout, сроки cleanup или MCP handshake.
- Не читать .env; значение брать только из окружения процесса.
- Не выводить исходное ошибочное значение настройки, содержимое окружения или необработанные Error-объекты.
- Не выполнять коммит, push, публикацию, закрытие issue или изменение старых планов.

## Проверки

Рабочая папка: D:\Projects\timeweb-mcp.

- `npm run test:smoke-start` — проходят существующие сценарии и новые проверки разбора/CLI. Если тесты вынесены в отдельный файл, подключить его к этой команде.
- `npm run smoke` без TIMEWEB_SMOKE_START_TIMEOUT_MS, с пустым TIMEWEB_TOKEN — startup сообщает timeoutMs=5000, оба smoke проходят.
- `npm run smoke:startup-series` без настройки — metadata и все шесть результатов содержат timeoutMs=5000; каждый запуск сохраняет проверку stdout.
- Штатные startup CLI с TIMEWEB_SMOKE_START_TIMEOUT_MS=10000 — выбранный срок присутствует в metadata/результатах; остальные ограничения неизменны.
- Оба CLI с пустым, нечисловым или выходящим за диапазон значением — один безопасный configuration_error, ненулевой exit, сервер не запускается.
- `npm run verify` без настройки и с пустым TIMEWEB_TOKEN — проходят OpenAPI/route gate, все тесты, типы, сборка и оба smoke. Сообщить фактические PASS/FAIL/skipped.
- На доступном Linux/WSL повторить startup-тесты; POSIX-сценарий должен реально выполняться там. Windows skip этого сценария не выдавать за PASS.
- `git -c safe.directory=D:/Projects/timeweb-mcp diff --check` — нет whitespace-ошибок; новые untracked-файлы проверить отдельно.
- Просмотреть git status и diff: допустимы только изменения smoke-настройки, тестов, их команды запуска и документации.

GitHub CI нового изменения и физически холодный запуск обозначить NOTRUN, если фактически не выполнены. Не запускать CI публикацией в рамках этого этапа. При повторном локальном timeout сохранить диагностику; успешный повтор не аннулирует предыдущий отказ.

## Критерии готовности

- Default остаётся 5000 мс; явное корректное значение одинаково применяется обоими startup CLI.
- Некорректная настройка безопасно отклоняется до spawn, без вывода исходного значения.
- Выбранный timeout виден в результатах и metadata серии.
- Проверка stdout, однозначный итог, ненулевые коды отказов и ограниченный cleanup сохранены.
- Новые CLI-регрессии и существующий локальный verify проходят; skips и непроверенные среды указаны отдельно.
- Документация объясняет настройку и не утверждает, что первопричина исторического timeout устранена.
- Runtime-сервер, зависимости, lockfile и workflows не изменены; коммит, push и закрытие issue не выполнялись.
