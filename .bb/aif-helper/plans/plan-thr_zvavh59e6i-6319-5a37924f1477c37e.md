# Issue #21 — не требовать run_cmd для frontend-приложений

## Цель

Разрешить создание frontend-приложения без `run_cmd`. Для backend проверять наличие команды после применения настройки фреймворка и до POST создания.

Сохранить согласованную политику #20:

- явно переданная строка, включая `""`, имеет приоритет;
- default применяется только при `undefined`;
- пустая строка, возвращённая как default, также является допустимым строковым значением;
- отсутствие команды у backend нельзя скрывать автоматической подстановкой `""`.

## Ограничения

- Изменить только `src/tools/create-app.tool.ts` и `tests/tool-contracts.test.ts`.
- Использовать локальный коммит `b7b6a43` с исправлением #20 как основу. Предыдущие планы не изменять.
- Не менять обязательность `build_cmd`, API-клиент, DTO, `createAppAction` и общий механизм регистрации MCP-инструментов.
- Сохранить существующую raw-shape схему. Не вводить union-схему или статическую проверку, блокирующую backend до получения defaults.
- Не добавлять `.default("")`, `.catch("")`, `min(1)` или обрезку строки для `run_cmd`.
- Сохранить неизменность входа, выбранные provider/repository/preset, безопасные ошибки, отмену и отсутствие автоматических повторов.
- Сохранить фильтрацию action: frontend не отправляет `run_cmd`, backend не отправляет `index_dir`.
- Не обновлять зависимости, конфигурацию, OpenAPI, версию пакета и CI.
- Проверять offline, с фиктивными токенами и заблокированной сетью.
- Не выполнять облачные операции, коммит, push, публикацию или закрытие issue.
