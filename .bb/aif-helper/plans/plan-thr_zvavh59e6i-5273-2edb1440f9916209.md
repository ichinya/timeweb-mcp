# #20 — применять настройки деплоя к итоговому payload

## Цель

Исправить формирование запроса создания приложения: defaults должны заполнять отсутствующие параметры, а исходный объект должен оставаться неизменным.

Согласованный приоритет для `build_cmd`, `run_cmd` и `index_dir`:

1. Явное значение пользователя, включая `""`.
2. Значение из настройки выбранного фреймворка — только при `undefined`.
3. При отсутствии обоих значений — существующее поведение `createAppAction` для `build_cmd` и `index_dir`. Для backend без разрешённого строкового `run_cmd` действует проверка #21: `isError: true`, без POST и без автоматической подстановки `""`.

План согласован с последующим исправлением #21 в коммите `b6c80b9`: `run_cmd` необязателен в MCP-схеме; frontend его не отправляет, backend использует явную строку либо default выбранного фреймворка. Явное `""` и строковый default `""` допустимы. Неверный тип явно переданного значения отклоняется до API-чтений; отсутствие или неверный тип выбранной backend-команды после defaults — до POST.

## Границы изменений

Изменить только:

- `src/tools/create-app.tool.ts`;
- `tests/tool-contracts.test.ts`.

Сохранить выбор provider/repository/preset, обработку ошибок, отмену и отсутствие автоматических повторов. В action сохранить разделение: frontend отправляет `index_dir`, backend — `run_cmd`.

Изменение обязательности `run_cmd` уже выполнено отдельно в #21; сохранить его. Обязательность `build_cmd` не менять. Не обновлять зависимости, API-клиент, DTO, версию пакета и CI. Не выполнять облачные операции, коммит, push или закрытие issue в рамках реализации.

Уточнение по замечаниям проверки изменяет только этот план. Выполненные отметки сохранены из предыдущей реализации; они не подтверждают повторную проверку уточнённых требований и не разрешают откатывать #21.
