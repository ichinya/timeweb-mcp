# Ответы клиента баз знаний

`KnowledgeBasesApiClient` читает `knowledge_bases` в списках v1/v2 и
`knowledge_base` в get/create/update. Источник — официальный
[OpenAPI Timeweb](https://timeweb.cloud/api-docs-data/bundle.json), сверка 2026-11-10.
Локальная спецификация описывает актуальные имена, а parser дополнительно принимает
исторические `knowledgebases` / `knowledgebase`. Наличие старого формата в текущем
production не подтверждено.

Если присутствуют оба имени, каждый вариант проверяется независимо и данные должны
быть одинаковыми, включая дополнительные поля. Неверный вариант не скрывается
fallback к другому. Пустой массив — успешный список; отсутствие поля, `null`, неверная
форма или некорректные обязательные поля — `ServerException` с `invalid_response`.

Проверяются базовые типы полей базы знаний и различия версий: `documents` для v1,
`documents_count` для v2. В legacy-формате сохраняется прежняя допустимость отсутствия
`description` и `last_sync`, а числовые поля принимаются без нового требования целочисленности.
Дата продления подписки может быть `null`; `project_id` необязателен.
Полная рекурсивная проверка документов не выполняется. `meta` и `response_id` не
являются частью возвращаемого клиентом значения и этим parser не проверяются.

Публичные сигнатуры не изменены: списки возвращают массивы, остальные три метода —
объект. Данные и дополнительные поля сохраняются, запросы не повторяются.
Ошибки разбора имеют `outcome: unknown`, для чтений — семантику `read`, для
create/update — `mutation`: изменение могло выполниться; перед повтором необходимо
проверить состояние ресурса. Исходные payload и исключения не включаются в диагностику.

Fixtures составлены по официальным схемам и примерам, а не по live-ответам.
Проверки выполняются с fake adapter и запретом сети. Эти операции не зарегистрированы
как MCP-tools. Авторизованный Timeweb API не проверен; production-совместимость неизвестна.
