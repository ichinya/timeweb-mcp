# Ошибки API и неизвестный результат операции

`BaseApiClient` сохраняет успешный `Promise<T>` и выбрасывает `ServerException` с
неизменяемым `failure`. `NoTokenException` остаётся отдельным классом Error,
но также предоставляет этот безопасный контракт. Конструкторы API без аргументов
работают как прежде. `formatRequestError` формирует публичный текст без сырых
сообщений провайдера, stack/cause, HTTP-конфигурации и пользовательских параметров.

## Классификация

- `kind`: local, auth, validation, rate_limit, http, server, timeout, network,
  cancelled, invalid_response, unexpected.
- `outcome=not_sent`: токен отсутствует, signal уже отменён до вызова транспорта
  либо MCP scope уже завершён. Предварительная отмена имеет приоритет над токеном.
- `outcome=rejected`: только HTTP 401/403. Основание — раздел «Ответы» в
  `specs/openapi.json` (`info.description`): ошибка аутентификации либо
  аутентификация прошла, но прав недостаточно. Для этого API такие запросы
  отклоняются контролем доступа. Fixtures не являются самостоятельным
  доказательством поведения production.
- `outcome=unknown`: остальные сбои после возможного dispatch, включая
  400/422 (validation), 429 (rate_limit), 408/ECONNABORTED/ETIMEDOUT (timeout),
  5xx (server), отмену, сетевую ошибку, неоднозначный HTTP-ответ или ошибку
  разбора успешного ответа (invalid_response). Поле AxiosError.request не
  доказывает, что запрос дошёл либо не дошёл до провайдера.

Это две независимые оси: распознанная ошибка параметров не доказывает отсутствия
эффекта, а отмена ожидания не откатывает изменение. Неизвестные исключения
обозначаются как unexpected, а не как доказанная недоступность Timeweb.

Успешные ответы с Content-Type application/json или подтипом +json разбираются
строго: malformed JSON становится invalid_response/unknown даже после HTTP 201.
JSON-строки, числа, null и другие корректные JSON-значения декодируются один раз.
Для YAML/text (включая kubeconfig), ответов без тела 204/205 и HTTP-ошибок
сохраняются прежние преобразования Axios. Декодирование не проверяет DTO и
не доказывает, что изменение ресурса не состоялось.

## Повторы и диагностика

Автоматические повторы и reconciliation отсутствуют. `automaticRetry=false`
всегда. При unknown рекомендация `safe_read` допустима для чтения, для
mutation/unspecified — `reconcile_before_repeat`. Иначе — `no_automatic_retry`.
По умолчанию GET/HEAD считаются read, остальные методы unspecified. Внутренний
прямой вызов может передать явную семантику; MCP hints её не определяют.
`ServersApiClient.createServer(data, options?)` явно задаёт mutation и принимает
необязательные signal/operation; он также работает через контекст MCP без options.
Ни рекомендация, ни Retry-After не запускают второй запрос.

Сохраняются HTTP-статус, transport code из закрытого набора, только известный
provider code, UUID response ID и Retry-After. Неизвестные значения отбрасываются.
Произвольные message/error_code/operation не пересылаются клиенту. Retry-After
принимается как целое число секунд либо IMF-fixdate; неоднозначные значения,
отрицательные/дробные числа и переполнение игнорируются. Прошедшая дата даёт 0.
Числа не уменьшаются до произвольного лимита.

## Отмена и время жизни

Production-обёртки tools/resources запускают отдельный AsyncLocalStorage scope
со стабильным именем из реестра и сигналом MCP. Явный signal прямого API-вызова
объединяется с ним: любой сигнал отменяет запрос. Axios defaults не изменяются.
Сигналам не копируется пользовательский reason. Listeners снимаются в finally.
После выхода handler scope закрыт: detached callback не может начать новый
HTTP-запрос. Параллельные вызовы не разделяют состояние отмены.

После отмены MCP клиент может уже не ожидать ответ; гарантируется завершение
локального ожидания и безопасная классификация, а не доставка финального content.
Используются API, доступные в Node 20.0.0, без AbortSignal.any.

## Offline-проверки

`npm run test:transport` проверяет типы тестов, собирает их отдельно от production
dist и запускает node:test. Fake adapters используют явный dummy token,
а реальные сетевые вызовы заблокированы в тестовом процессе. Журнал fake provider
записывает эффект независимо от исключения клиента. Проверяются один POST/один
эффект при потерянном ответе, ошибки и Retry-After, отмена/изоляция через MCP
InMemoryTransport, секреты в message/JSON/inspect/logs/MCP content и очистка scope.
Это не доказательство live-совместимости Timeweb; она здесь не проверяется.

Изменение `isError`, аннотаций инструментов, SSH DTO, endpoint/base URL,
зависимостей и CI остаётся в отдельных issues.
