# Пагинация серверов и доменов

`list_servers` и `list_domains` возвращают одну страницу. Параметры необязательны:

- `limit`: целое от 1 до 100, по умолчанию 100;
- `offset`: неотрицательное безопасное целое, по умолчанию 0;
- сумма `offset + limit` также должна быть безопасным целым JavaScript.

Граница 100 — локальная политика нового постраничного интерфейса, а не
документированный максимальный limit Timeweb API. Defaults применяются только
при отсутствии значения (`undefined`); `null` не означает значение по умолчанию.

Например, `list_servers` с `{ "limit": 20, "offset": 0 }` показывает количество
полученных записей, `meta.total` и параметры следующего вызова, если он доступен.
Для продолжения используйте указанное смещение: оно увеличивается на фактическое
число записей, даже если провайдер вернул меньше limit. Каждый вызов выполняет
ровно один GET. Автоматического обхода и повторов нет.

Пустая страница останавливает продолжение. При `total=0` аккаунт пуст; при
положительном total по запрошенному смещению нет записей. Если пустая страница
получена до total или количество записей расходится с total, ответ указывает
расхождение, а не заявляет полноту списка. Offset-пагинация не обеспечивает
согласованный снимок: между вызовами записи и total могут измениться.

Неправильные параметры отклоняются до отправки. Отсутствующие или некорректные
коллекция/metadata, а также превышение limit в ответе дают безопасную ошибку
`invalid_response` с семантикой чтения. Total не заменяется длиной массива.

## Прямые вызовы и совместимость

Новые `ServersApiClient.listServersPage(params?, options?)` и
`DomainsApiClient.listDomainsPage(params?, options?)` возвращают
`{ items, total, limit, offset, nextOffset }`. `nextOffset` равен `null`, когда
продолжение не указано. `options` поддерживает существующие transport options,
включая отмену; прямой signal не отключает родительский MCP signal.

`listServersPageAction` и `listDomainsPageAction` передают страницу инструментам.
Существующие `listServers()`/`listDomains()` и массивные actions сохраняют
прежний контракт первой страницы без metadata; они не получают новые строгие
проверки metadata. Для обхода страниц используйте новые методы.

## Соседние случаи для последующей сверки

При исследовании #24 подтверждено чтением кода:

- `src/api/balancers.ts`, `listBalancers`: принимает limit/offset, возвращает
  только `response.balancers`, теряя meta.total.
- `src/api/images.ts`, `listImages` и `listImageDownloads`: принимают limit/offset,
  возвращают массивы без meta.total.
- `src/api/kubernetes.ts`, `listClusters` и `listNodeGroupNodes`: принимают
  limit/offset, возвращают массивы без meta.total.
- `src/api/domains.ts`, `listDnsRecords`: не предоставляет limit/offset и
  возвращает только массив. Локальный `specs/openapi.json` предусматривает оба
  параметра для GET `/api/v1/domains/{fqdn}/dns-records`.

Наличие total само по себе не доказывает одинаковые правила пагинации всех API.
Перед отдельным исправлением каждого endpoint нужны сверка его актуального
контракта и проверки вызывающих actions/tools. Эти методы в #24 не изменяются.

Источник параметров серверов и доменов: [официальный OpenAPI Timeweb](https://timeweb.cloud/api-docs-data/bundle.json),
сверенный при исследовании 2026-11-10. Авторизованные live-запросы не выполнялись;
offline-тесты не подтверждают production-поведение.
