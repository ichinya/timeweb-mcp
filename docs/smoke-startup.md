## Поведение smoke-start

`node scripts/smoke-start.mjs` запускает `dist/index.js` через текущий Node
с `windowsHide: true`, ожидает существующий маркер готовности в stderr
и проверяет отсутствие любых байтов в stdout до MCP-ввода.

Порог готовности сохранён: **5000 мс**, без CLI/env-настройки. Для сценарных
тестов модуль `scripts/startup-probe.mjs` принимает внутренние параметры
команды, сроков и создания процесса; штатный CLI их не раскрывает.

Итоговая строка содержит только фиксированный префикс и JSON:

- `status`: ready, spawn_error, early_exit, timeout, stdout_noise или cleanup_timeout;
- `startupStatus`: исходный результат до возможного отказа cleanup;
- `readyMs`: время до готовности, либо null; `elapsedMs`: время до итогового результата;
- `timeoutMs`, `cleanupMs`, PID при наличии, exit code и signal;
- `spawnError`: код из разрешённого набора либо UNKNOWN;
- `stdoutBytes`, `stderrBytes`, `cleanupFailed`.

Время измеряется монотонными часами. После ready/ошибки запрашивается SIGTERM;
закрытие процесса и потоков ожидается до 1000 мс. При необходимости отправляется
SIGKILL с ещё одним интервалом 1000 мс. Если close не пришёл, результат становится
cleanup_timeout, потоки уничтожаются, процесс отсоединяется от event loop.
Это ограничение ожидания теста, а не заявление об успешном завершении процесса.
Задержки event loop могут увеличить фактическое время выполнения таймеров.

Timeout не отменяется поздним маркером. При готовности проверяется и фактическое
время поступления маркера, чтобы задержанный callback таймера не дал ложный PASS.
Вывод, поступивший в stdout во время cleanup после ready, также означает отказ.
Каждый запуск CLI печатает один итог и завершается ненулевым кодом при отказе.

Произвольные stdout/stderr и Error.message/stack не печатаются. Вместо полного
буфера stderr хранится только хвост для распознавания разделённого маркера;
общий объём вывода учитывается счётчиками.
