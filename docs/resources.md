# JSON-ресурсы MCP

Все шесть ресурсов объявлены как `application/json` в metadata регистрации и в
каждом элементе `contents`. `text` содержит JSON, сериализованный ровно один раз;
URI результата совпадает с URI чтения.

- `allowed-presets://all`: объект с массивами `frontend_presets` и `backend_presets`.
  Пустой каталог сохраняет оба поля с пустыми массивами.
- `deploy-settings://all`: массив настроек деплоя.
- `database-presets://all`: массив пресетов баз данных, без Markdown-заголовка.
- `vpc://all`: массив VPC.
- `vcs-provider://all`: массив провайдеров. Допустимое отсутствие optional-поля
  providers (`undefined` в результате action) означает пустой массив.
- `vcs-provider://{provider_id}/repositories`: массив репозиториев. Существующий
  action уже нормализует отсутствие repositories в пустой массив; ресурс проверяет
  именно результат action и не восстанавливает скрытые им нарушения wire-контракта.

Пустой массив является успешным результатом. Отсутствие обязательного результата,
неверная верхнеуровневая форма или ошибка JSON-сериализации являются ошибкой чтения.
Полная проверка DTO каждой записи не проводится. Верхнеуровневые `null`, false
или строки не заменяются пустым каталогом.

## Ошибки и совместимость

Ошибки чтения передаются через JSON-RPC: `-32602` для контролируемой локальной
ошибки `provider_id`, `-32603` для ошибок API, данных и внутренних исключений.
Клиент `readResource` отклоняет promise; успешного `contents` с текстом ошибки и
tool-флага `isError` нет. Произвольный `McpError` зависимости также санитизируется,
а не пересылается с исходными message/data. Сообщения не содержат сырых тел,
Authorization, stack или cause; используются безопасные сообщения транспорта.

Клиентам, ранее читавшим сообщения об отсутствии данных или сбое как содержимое,
следует разбирать JSON пустого результата и обрабатывать протокольную ошибку.
Успешные структуры данных, имена, пять статических URI и один template URI
сохранены. Обработка неизвестного URI остаётся за SDK.

Ресурсы используют отдельную границу ошибок с прежним request context: стабильное
имя операции, изоляция отмены, снятие listeners и запрет нового HTTP dispatch из
закрытого scope. Обработка tools и общий HTTP-транспорт не изменяются. После
отмены клиент может уже не ожидать ответа; доставка финальной ошибки не обещается.

Контракт проверяется offline через production-регистрацию и InMemoryTransport.
Авторизованные live-запросы Timeweb не выполнялись; production-совместимость
этими тестами не подтверждается.
